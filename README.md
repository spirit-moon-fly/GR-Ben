# GR-Ben: A Multi-Domain Benchmark for Process Reward Models

GR-Ben is a benchmark for evaluating **Process Reward Models (PRMs)** on their ability to detect reasoning errors across diverse domains. Each sample contains a multi-step reasoning chain generated by an LLM, annotated with the index of the first erroneous step (or `-1` if the reasoning is fully correct).

---

## Dataset Overview

| Property | Value |
|----------|-------|
| Total samples | 3,595 |
| Domains | 9 |
| LLM generators | 15 |
| Annotation | Step-level error localization |

### Domains

| Domain | # Samples |
|--------|-----------|
| Causelogics | 402 |
| Analobench | 402 |
| FOLIO | 411 |
| Logiqa | 399 |
| MIRAGE | 400 |
| physics | 392 |
| biology | 399 |
| chemistry | 391 |
| computer-science | 400 |

---

## Data Schema

Each line in `data/GR-BEN.jsonl` is a JSON object:

| Field | Type | Description |
|-------|------|-------------|
| `id` | str | Unique sample ID |
| `domain` | str | One of the 9 domains above |
| `generator` | str | LLM that produced the reasoning chain |
| `problem` | str | The question / problem statement |
| `steps` | list[str] | List of reasoning steps |
| `label` | int | First erroneous step index, **1-indexed** (`-1` = all correct, `k ≥ 1` = step k is the first error) |
| `final_answer_correct` | bool | Whether the final answer is correct |
| `error_type` | str\|null | Error category |
| `reason` | str\|null | Human annotation explaining the error |

```json
{
  "id": "Causelogics-1",
  "domain": "Causelogics",
  "generator": "Llama-3.2-3B",
  "problem": "...",
  "steps": ["Step 1 ...", "Step 2 ...", "Step 3 ..."],
  "label": 2,
  "final_answer_correct": false,
  "error_type": "Logical error",
  "reason": "Step 2 incorrectly applies the rule..."
}
```

---

## Evaluation Metrics

| Metric | Definition |
|--------|-----------|
| **Acc_Corr** | Fraction of `label=-1` samples correctly predicted as error-free |
| **Acc_Err** | Fraction of `label≥1` samples where the exact error step is predicted |
| **F1** | Harmonic mean of Acc_Corr and Acc_Err |

The **Average** row in evaluation output is the **macro-average** across all 9 domains (each domain weighted equally, regardless of sample count).

## Installation

```bash
# Create environment (Python 3.9)
conda create -n grben python=3.9 -y
conda activate grben

# Install PyTorch with the CUDA version matching your system
# See https://pytorch.org/get-started/locally/ for the exact command, e.g.:

# Install remaining dependencies
pip install -r evaluation/requirements.txt
```

## PRM Evaluation

### Example models

The built-in adapter supports Qwen-series PRM models. Any PRM that follows the same interface can be evaluated using the `eval` subcommand with pre-computed scores (see below).

| Example Model | HuggingFace |
|---------------|-------------|
| Qwen2.5-Math-PRM-7B | [Qwen/Qwen2.5-Math-PRM-7B](https://huggingface.co/Qwen/Qwen2.5-Math-PRM-7B) |
| Qwen2.5-Math-PRM-72B | [Qwen/Qwen2.5-Math-PRM-72B](https://huggingface.co/Qwen/Qwen2.5-Math-PRM-72B) |
| Qwen2.5-Math-7B-PRM800K | [Qwen/Qwen2.5-Math-7B-PRM800K](https://huggingface.co/Qwen/Qwen2.5-Math-7B-PRM800K) |

### Run inference

```bash
# Single GPU
python evaluation/run_prm_eval.py infer \
    --data data/GR-BEN.jsonl \
    --model_type qwen \
    --model_path /path/to/Qwen2.5-Math-PRM-7B \
    --model_key Qwen2.5-Math-PRM-7B \
    --output_dir results/qwen7b \
    --device cuda:0

# Multi-GPU (device_map=auto, e.g. for 72B)
python evaluation/run_prm_eval.py infer \
    --data data/GR-BEN.jsonl \
    --model_type qwen \
    --model_path /path/to/Qwen2.5-Math-PRM-72B \
    --model_key Qwen2.5-Math-PRM-72B \
    --output_dir results/qwen72b
```

### Compute metrics from pre-saved results

Bring your own JSONL where each line has `gt_label` (copied directly from the dataset `label` field) and `probs` (per-step scores, higher = more likely correct):

```bash
# Fixed threshold
python evaluation/run_prm_eval.py eval \
    --input_file results/my_model_results.jsonl \
    --threshold 0.5

# Auto-tune threshold
python evaluation/run_prm_eval.py eval \
    --input_file results/my_model_results.jsonl \
    --tune_threshold
```

## LLM Evaluation

### Run with built-in presets

```bash
# GPT-5.2 — Fast (no thinking) + Slow (high reasoning_effort)
python evaluation/run_llm_eval.py batch \
    --data data/GR-BEN.jsonl \
    --output_dir results/llm/gpt5 \
    --preset gpt5 \
    --api_key YOUR_KEY

# Gemini-3-flash — Fast + Slow variants
python evaluation/run_llm_eval.py batch \
    --data data/GR-BEN.jsonl \
    --output_dir results/llm/gemini \
    --preset gemini \
    --api_key YOUR_KEY
```

### Run a custom model

```bash
python evaluation/run_llm_eval.py infer \
    --data data/GR-BEN.jsonl \
    --model your-model-name \
    --model_key MyModel \
    --base_url https://api.openai.com/v1/chat/completions \
    --api_key YOUR_KEY \
    --mode Slow \
    --thinking_type reasoning_effort \
    --output_dir results/llm/mymodel
```

`--thinking_type` options: `reasoning_effort` (OpenAI o-series), `enable_thinking` (DeepSeek), `budget_tokens` (Claude). Omit for standard models.

### Compute metrics from saved results

```bash
python evaluation/run_llm_eval.py eval \
    --input_dir results/llm/mymodel \
    --output results/llm/mymodel/summary.csv
```
